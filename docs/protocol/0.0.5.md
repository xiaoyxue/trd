# Stream protocol 0.0.5

- **Version:** `0.0.5`
- **Status:** Current — the **only** version the renderer accepts.
- **Compatibility:** **none.** The protocol is **not backward compatible**: the
  renderer accepts `0.0.5` only and **hard-rejects** any other declared
  `trd.protocol.version` (see the
  [no-backward-compat policy](../../AGENTS.md)). Older iterations
  (`0.0.1`–`0.0.4`) were removed to simplify the code (#90); this file is the
  single, self-contained specification of the wire format.

This is the complete schema the rendering core consumes (stdin) and produces
(stdout). It is an **Apache Arrow IPC stream**: one schema message followed by N
record-batch messages, with `1 row = 1 frame`.

## Conventions

- Matrices are **column-major** and right-handed; the projection targets **wgpu
  clip space** (`z ∈ [0, 1]`). The vertex transform is the MVP chain
  `clip = P · V · M · (position, 1)`.
- The protocol version is carried in schema-level metadata under the key
  **`trd.protocol.version`** (`MAJOR.MINOR.PATCH`) and must be exactly `0.0.5`.
- An optional schema-metadata key **`trd.stream.frame_rate`** (float, frames/sec,
  default **30**) declares the stream's intended playback rate — like a video
  file's fps. Front-ends play at this rate (speed = fps); `trd-cli` copies it
  through to the rendered image stream so `scripts/encode.py` encodes the
  GIF/WebP at the same rate.

## Wire format — mesh-first framing

Every stream is **mesh-first**: a leading **mesh** table, an optional **texture**
table, then the terminal **params** table.

```
[ mesh stream ]  [ texture stream? ]  [ params stream ]
```

The three sub-streams are told apart by **schema sniffing**: a stream carrying a
`position` column is the mesh table; otherwise one carrying an `rgba` column is
the texture table; the final stream (per-frame columns) is the params table.
There is **no params-only fallback** — the input must begin with a mesh table.

## Mesh stream schema

One row = one mesh; geometry is nested in list columns.

| Column | Arrow type | Required | Meaning |
|---|---|:--:|---|
| `position` | `List<FixedSizeList<Float32>[3]>` | yes | Per-vertex `(x, y, z)`. |
| `color` | `List<FixedSizeList<Float32>[3]>` | optional | Per-vertex `(r, g, b)`; absent → white. |
| `uv` | `List<FixedSizeList<Float32>[2]>` | optional | Per-vertex `(u, v)`, top-left texel origin; absent → `(0, 0)`. |
| `index` | `List<UInt32>` | optional | Triangle indices; absent → sequential. |

Decoded by `Mesh::from_arrow` and drawn with `draw_indexed`. A loaded mesh
renders **centered at the world origin and uniformly scaled to fit**
(`s = target / max_extent`), a `base_model` composed beneath the per-frame
`model`. `scripts/obj_to_arrow.py` encodes an OBJ into the mesh stream (emitting
`uv` as `[u, 1 − v]` from the OBJ's `vt` records).

## Texture stream schema (optional)

One row = one image, spliced between the mesh and params streams.

| Column | Arrow type | Meaning |
|---|---|---|
| `rgba` | `FixedSizeList<UInt8>[H·W·4]` | Interleaved RGBA8, row-major, carrying the canonical `arrow.fixed_shape_tensor` extension (shape `[H, W, 4]`). |

Height/width are read from the extension metadata (self-describing). Decoded by
`ImageTexture::from_arrow`; the first non-empty row is bound as the sampled
albedo. `scripts/texture_to_arrow.py` encodes an image (with `--max-size`
downscaling to stay within the portable 2048² limit).

## Params stream schema

One row = one frame. All columns are **optional/additive**; a frame is typically
driven by its `draws` list plus a per-frame camera.

| Column | Arrow type | Meaning |
|---|---|---|
| `model` | `FixedSizeList<Float32>[16]` | Column-major 4×4 **model** matrix (object → world) for the single-object fallback. Defaults to identity when the frame is driven entirely by `draws`. |
| `k` | `FixedSizeList<Float32>[9]` | **CV** camera intrinsics (column-major 3×3 pinhole `K`). Derives the projection `P`. |
| `pose` | `FixedSizeList<Float32>[16]` | **CV** camera-to-world pose (4×4). The view matrix is `V = inverse(pose)`. |
| `eye`, `target`, `direction`, `up` | `FixedSizeList<Float32>[3]` | **CG** look-at vectors. |
| `fovy`, `aspect`, `znear`, `zfar` | `Float32` | **CG** perspective parameters. |
| `draw_mesh` | `List<UInt32>` | Per-instance mesh indices (0-based, into the mesh table). |
| `draw_model` | `List<FixedSizeList<Float32>[16]>` | Per-instance 4×4 models (composed beneath each mesh's preview transform). Must be equal-length with `draw_mesh` per row. |
| `frame_path` | `Utf8` | Filesystem path of the frame's background image, resolved by the **native** shell (relative to `trd --frames-base <dir>` / `trd-app --frames-base <dir>`). |
| `frame_url` | `Utf8` | URL of the frame's background image, resolved by the **browser** shell. |

### Camera

Resolved in precedence order per frame: a **CV** camera from `k` + `pose`
(`view = inverse(pose)`), else a **CG** look-at from `eye` + `target` (or `eye` +
`direction`) with `up`, `fovy`, `aspect`, `znear`, `zfar`. Absent any camera
column, an identity view and default perspective are used. CV wins per component.

### Draw list

A frame with `draw_mesh` + `draw_model` renders each referenced mesh at its own
model in one instanced batch — each entry places mesh `draw_mesh[i]` under model
`draw_model[i]`. Absent a draw list, one instance of mesh 0 is placed by the
frame's own `model`. `scripts/jsonl_to_arrow.py` accepts a convenience
`"draws": [{"mesh", "model"}, …]` JSONL form and emits the two Arrow columns.

### Background frame reference

`frame_path` (native) and `frame_url` (browser) are **per-row** (one row = one
frame), so the background image can change every frame (e.g. a video's stills,
one per frame). A **null** or **empty** value means that frame has no background.
When both columns are present, the unified decoder (`trd-core`) prefers
`frame_path`, then falls back to `frame_url`. The core **never reads the file
or the URL** — it only decodes the reference string and hands it to the shell,
which performs the I/O + image decode. `scripts/extract_frames.py` (#76) is the
reference producer: it writes a video's stills to `frames/frame_000000.png …` and
an Arrow manifest carrying both `frame_path` and `frame_url`.

## Rendering

Everything the renderer draws is a `DrawableObject` (a mesh, an AABB gizmo, a
coordinate-axes gizmo, or the background frame plane). Meshes render **filled**,
as a **wireframe** line list (`--wireframe`), or **textured** (`--textured`,
mutually exclusive with wireframe): a `texture_2d<f32>` + `sampler` samples the
bound texture at each vertex UV (`Rgba8UnormSrgb`, linear, clamp-to-edge). A
textured draw with no bound texture samples a default 1×1 opaque-white texel.

### Background frame plane

A frame carrying a resolved background image is composited by a
`DrawableObject::FramePlane` primitive drawn **first** in the mesh pass:

- The plane is a shader-generated **fullscreen triangle** authored directly in
  clip space (it ignores the camera), sampling the background texture.
- It is drawn with **depth writes off** and depth compare `Always`, so the mesh
  scene + gizmos (AABB, axes) z-composite **on top** of it.
- The background texture is uploaded to a reused **`Rgba8UnormSrgb`** GPU texture
  (texels linearized on read, matching the mesh textured path and the sRGB output
  target), sampled **linear**, **clamp-to-edge**, with **no mipmaps**. It is
  (re)created only when the image resolution changes, so a fixed-resolution video
  allocates once and every later frame is a plain texture write.
- **Fit:** the image fills the whole viewport. `Stretch` (default) ignores aspect;
  `Cover` preserves aspect and center-crops the overflowing axis. Both avoid
  letterbox bars.

The background frame texture is a **second, separately-updated** binding, distinct
from the mesh albedo texture: the albedo arrives inside the Arrow texture stream
and skins the meshes, while the background arrives at the shell boundary (from
`frame_path`/`frame_url`) and skins the frame plane.

## Timing model

The animation is a **sequence of frames** (one row = one frame); playback follows
the classic video-player model:

- **`frame_rate` (the stream's fps) sets the speed** — advancing `frame_rate`
  frames per second. `trd-app` accepts `--fps` to override it.
- **Presentation is decoupled from the monitor refresh (vsync).** `trd-app`
  presents at the playback fps by default (non-vsync); pass `--vsync` to lock to
  the refresh rate.
- The same content at the same fps plays at the same speed.

## Output schema

Four `fixed_shape_tensor<UInt8>` channels `r`, `g`, `b`, `a` of shape
`[height, width]`, one row per rendered frame. The output stream is 1:1 with the
input params stream; output batch boundaries mirror the input batches, so memory
stays bounded to a single batch in flight.

## Example (input)

Extract a video's frames + manifest, then render a mesh scene composited over the
per-frame stills:

```sh
# 1) video -> frames/frame_000000.png … + frames.arrow (frame_path/frame_url)
scripts/extract_frames.py input.mp4 -o output/clip

# 2) [mesh][params-with-frame_path] on one stdin; --frames-base resolves frame_path
{ scripts/obj_to_arrow.py bunny.obj;
  scripts/jsonl_to_arrow.py frames.over_video.jsonl; } \
  | trd --width 1024 --height 1024 --frames-base output/clip
```

Without `--frames-base`, `frame_path` columns are ignored (the scene renders over
the black clear).
