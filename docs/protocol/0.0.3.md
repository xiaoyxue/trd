# Stream protocol 0.0.3

- **Version:** `0.0.3`
- **Status:** Current
- **Since:** this release
- **Compatibility:** backward-compatible with [0.0.2](./0.0.2.md) and
  [0.0.1](./0.0.1.md) — a params-only stream decodes and renders identically;
  decoders accept `{0.0.1, 0.0.2, 0.0.3}`.

## Wire format

Apache Arrow IPC streaming format. `0.0.3` introduces **multi-stream framing**: an
optional leading **mesh** IPC stream, **concatenated before** the params IPC
stream on the same input (two schema+batches sequences back-to-back):

```
[ mesh stream ]  [ params stream ]
```

Both are ordinary Arrow IPC streams (schema message + N record-batch messages +
end-of-stream). The reader consumes the first stream to its end-of-stream marker,
then reads the second from the same byte source. A **params-only** stream (no
leading mesh) is exactly a `0.0.1`/`0.0.2` stream and renders the built-in
hello-triangle — full backward compatibility.

The two streams are told apart by **schema sniffing**: a first stream whose schema
has a **`position`** column is a mesh table; otherwise the input is a legacy
params-only stream.

## Mesh stream schema

**One row = one mesh** (the first row is decoded; multi-mesh scenes are a
follow-up). Geometry is nested in **list columns** so per-vertex and per-index
data of differing lengths coexist in a single record batch:

| Column | Arrow type | Required | Meaning |
|---|---|:--:|---|
| `position` | `List<FixedSizeList<Float32>[3]>` | yes | Per-vertex positions `(x, y, z)`, one inner `FixedSizeList[3]` per vertex. |
| `color` | `List<FixedSizeList<Float32>[3]>` | optional | Per-vertex RGB; must match the `position` length. Absent → all white. |
| `index` | `List<UInt32>` | optional | Triangle-list indices into the vertices. Absent → the vertices are a non-indexed triangle list (count must be a multiple of 3). |

Validation (`Mesh::from_arrow`) rejects a missing/mistyped `position`, a `color`
whose length differs from `position`, an `index` out of range, a non-indexed
vertex count not divisible by 3, null values, and an empty table.

### Preview transform (scale-to-fit)

A loaded mesh is rendered **centered and uniformly scaled to fit**: the core
applies a `base_model = scale_to_fit · translate(-aabb.center())`, where
`scale_to_fit` is a **uniform** `s = target / max_extent(aabb)` (`target` ≈ 2
world units). It composes **beneath** the per-frame `model`, so the effective
transform is:

```
clip = P · V · (M · base_model) · (position, 1)
```

An arbitrary-unit, off-origin asset (e.g. `assets/meshes/bunny.obj`) therefore
renders centered at the world origin at a reasonable size, while a per-frame
`model` (e.g. a rotation) still animates on top. The preview lives entirely in the
core (single source of truth); producers only send per-frame params.

## Params stream schema

Unchanged from [0.0.2](./0.0.2.md) (`center`/`size`/`theta` + optional
`model`/`k`/`pose`). The mesh, when present, replaces the hello-triangle geometry;
the params drive the per-frame MVP as before. The params stream may itself be
tagged `0.0.1` or `0.0.2` — the mesh stream carries the `0.0.3` version marker.

## Output schema

Unchanged from [0.0.1](./0.0.1.md) — four `fixed_shape_tensor<UInt8>` channels
`r, g, b, a` of shape `[height, width]`, one row per rendered frame.

## Example (input)

Encode an OBJ into the leading mesh stream, then concatenate the params stream:

```sh
# [mesh][params] on one stdin, rendered by trd-cli / trd-app
{ scripts/obj_to_arrow.py assets/meshes/bunny.obj;
  scripts/jsonl_to_arrow.py examples/frames.turntable.jsonl; } \
  | trd --width 256 --height 256
```

`examples/render.sh --mesh assets/meshes/bunny.obj examples/frames.turntable.jsonl
output/bunny.gif` wires this end-to-end.

## Changes from 0.0.2

See [`CHANGELOG.md`](./CHANGELOG.md). Summary: adds the optional leading **mesh**
Arrow stream (nested-list geometry), the multi-stream `[mesh][params]` framing,
and the scale-to-fit preview transform. Params-only streams are unaffected.
