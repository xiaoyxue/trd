# AGENTS.md

Guidance for agents working in this repository.

> **In one minute.** `trd` is **one** Rust + wgpu rendering core (`crates/trd-core`)
> that draws natively, headlessly and in the browser; JS/TS is only a bootstrap.
> Work in a **[git worktree](#worktrees)** off an up-to-date `main`, open a
> **draft PR early**, and before calling it done pick a
> **[test level](#test-levels--l1--l2--l3)** from what your diff touches —
> **L1** (no GPU) / **L2** (+ goldens) / **L3** (+ end-to-end) — run it on **both
> Windows and Linux**, and post the [verification matrix](#verification-matrix).
> **There is no CI: every gate is run by hand, locally.** And any change that
> reaches pixels must land the golden suite green on a real GPU.
>
> This file says *which* gates a change owes and how to report them;
> [`docs/testing.md`](docs/testing.md) says how to run them.

## Architecture

[`docs/architecture.md`](docs/architecture.md) is the full picture — render core,
targets, drawables, typed math, Arrow domains. These are the rules a change could
violate without anything noticing:

- **All rendering logic lives in Rust** (`crates/trd-core`); one codebase renders
  natively, headlessly and in the browser. **JS/TS is a thin bootstrap** — never
  call the WebGPU API from JS. Each increment is a **vertical slice**: it threads
  the whole stack and is independently end-to-end verifiable.
- **`crates/trd-wasm` is the only browser delivery surface**: the only crate with
  `#[wasm_bindgen]` exports, the only `cdylib`, the only one that may name
  `web-sys` — all three scanned by
  `crates/trd-wasm/tests/wasm_bindgen_containment.rs`. Before writing a
  `#[cfg(target_arch = "wasm32")]`, read
  [the resolution order](docs/architecture.md#prefer-moving-a-cfg-into-trd-wasm-over-living-with-one).
- **Browser demuxing/decoding is [mediabunny](https://mediabunny.dev/), always** —
  **delete rather than grow** the hand-written mp4box + `VideoDecoder` reader
  (`media/mp4-video.ts`), and put new media work behind the `FrameReader` seam
  (#290). The boundary and its one exception (the raw `moov` walk, because Rust
  needs a **rational** frame rate) are in
  [`docs/video-editing.md`](docs/video-editing.md#reader-boundary).
- **The input protocol is NOT backward compatible.** Only the current
  `trd_core::protocol::PROTOCOL_VERSION` (`0.0.6`) is accepted; anything else is
  hard-rejected, never silently upgraded. To evolve it, **bump the version and
  migrate all producers + fixtures in one change** (`scripts/*_to_arrow.py` stamp
  it; regenerate `stage{1,2}.arrow`). Never re-add retired versions (#82/#90).
- **The video-editing document (`trd.video_edit.version = 0.2.0`) is deliberately
  independent of `PROTOCOL_VERSION`** — no editor columns in `0.0.6`, no protocol
  bump for editor state.
- **Comments say *why*, not *what*; no block over 10 lines; cite an issue rather
  than re-litigating it.** The nine rules, their two deliberate exceptions, and
  the budgets are in [`docs/comments.md`](docs/comments.md); measure any of it
  with `python3 scripts/comment_audit.py --scope front-end`.

## Toolchain

**Dev shell:** `nix develop` (pinned Rust, `bun`, `wasm-bindgen-cli`, `biome`,
`typescript`, Vulkan); local `cargo` inside it is fine for iteration. **The flake
is the build system, not just a dev shell:**

| Command | What it produces |
|---|---|
| `nix build .#trd-cli` | native CLI, wrapped with Vulkan/GL libs. `nix run .#trd-cli -- --width 256 --height 256` runs the Arrow stream filter (frames on stdin → images on stdout) |
| `nix build .#trd-wasm` | the `wasm-bindgen` JS/TS library (`wasm-bindgen-cli` + `wasm-opt`) |
| `nix build .#web` (also `.#`) | the bun-bundled, HTTP-servable `dist/`; `nix run .#web` serves it (`PORT`, default 8080) |
| `nix flake check` | every non-GPU gate — exactly **L1** below |
| `nix fmt` | formats nix files (`nixfmt`) |

- **`nix build`/`nix flake check` only see git-tracked files** — `git add` new
  files first, or the sandbox won't include them.
- **Layout:** native binaries in `native/{trd-app,trd-gui-app,trd-gui-video-editing}`,
  reusable Rust in `crates/`, browser apps in `web/{viewer,gui-viewer,gui-video-editing}`.
- **`web/` is a Bun workspace** — `bun run check` / `format` / `typecheck` from its
  root (Biome is the lint gate). Each package stages its own copy of the one
  `crates/trd-wasm` build under `pkg/`; **no delivery surface imports another's
  build output** (#180). On a clean non-Nix checkout run
  `bun run --cwd <pkg> build:wasm` for all three, then `bun install --frozen-lockfile`.
  **Regenerate `web/bun.nix` whenever `web/bun.lock` changes** (`cd web && bun install`,
  `nix run github:nix-community/bun2nix -- -l web/bun.lock -o web/bun.nix`), then
  **delete the autogenerated `"trd-wasm" = copyPathToStore ...;` line** — that
  `file:` dep comes from the nix-built `trd-wasm`, not from a fetch.
- **GPU:** always render on the strongest discrete adapter, never an iGPU or
  llvmpipe. Selection, forcing, nixGL and WSL2:
  [`docs/testing.md#gpu`](docs/testing.md#gpu).

## Testing

**There is no CI.** `.github/workflows/ci.yml` exists but is
**`disabled_manually`** — nothing has run since 2026-07-21, and nothing runs on
push. **Every gate below is executed by hand, locally, on both platforms**, and a
PR page with no red X means only that nobody has looked yet. Run the smallest
command that covers the change while iterating, but a task is not complete until
every gate its **test level** requires has passed on **both** platforms — and
**the results are recorded on the PR**.

### Test levels — L1 / L2 / L3

Each PR declares a level, and **the level is derived from the diff, not from how
risky the change feels** — which makes the scope reviewable: a reviewer can
disagree with the *level* in one line instead of re-deriving which gates should
have run.

| Level | What it is | Adds over the level below |
|---|---|---|
| **L1** | **UT + IT** — everything needing no GPU and no display. | **Exactly `nix flake check`**: fmt, clippy native, clippy wasm32, `cargo test --workspace`, rustdoc (`-D rustdoc::broken_intra_doc_links`), `tsc --noEmit` + Biome. **The commands live in `flake.nix`, not here** — copying them is what let this file understate the wasm gate for weeks (#316/#181), so read the flake for exact arguments. |
| **L2** | **normal** — L1 plus the pixel-level regression net. Needs a real GPU. | `cargo test -p trd-core --test golden_render -- --ignored` (MSAA on **and** off, plus the PBR tone-map variants); `cargo test -p trd-core -- --ignored` (`render::gpu_tests`); `cargo test -p trd-gui --test gui_render -- --ignored` |
| **L3** | **full** — L2 plus end-to-end on a real device. | The [§3 e2e list and the §4 Windows matrix](docs/testing.md#the-tiers-in-full) (4.1 `trd-cli` · 4.2 `trd-app` window · 4.3 `trd-gui` window · 4.4 both web renderers · 4.5 native video editor · 4.6 browser video editor · 4.7 large-file seek) |

**The floor table.** Run `git diff --name-only origin/main` and take the
**highest** floor any changed path matches:

| The diff touches | Floor |
|---|---|
| `*.md`, `docs/**`, doc comments, or `flake.nix` **gates** | **L1** |
| test-only files (a `#[cfg(test)] mod tests`, a file under `crates/*/tests/`) | **L1** |
| `scripts/` tooling that reaches no pixel — `dev-env.ps1`, `encode.py`, `extract_frames.py`, `comment_audit.py` | **L1** |
| Rust/TS that changes behaviour but cannot reach pixels, a window or media — `crates/trd-placement`, `protocol/` decode, CLI arg parsing, `math/` helpers | **L2** |
| `crates/trd-core/src/render/**`, `src/shader/*.wgsl`, PBR/tone-map, `math/` transforms feeding the GPU `Uniform`, or the golden fixtures | **L3** |
| a delivery surface or shell — `native/**`, `crates/trd-wasm/**`, `crates/trd-gui/**`, `web/**` | **L3** |
| `web/gui-video-editing/src/media/**`, or anything else that demuxes, decodes or seeks | **L3, and §4.7 is required** |
| `scripts/golden_fixtures.py`, `scripts/{jsonl,obj,texture}_to_arrow.py`, `scripts/fiba_video_editing_bundle.py` — they regenerate goldens or stamp a version | **L3** |
| `PROTOCOL_VERSION` / `VIDEO_EDIT_VERSION` bump, or regenerated fixtures | **L3** |
| **no row matches** | **L3, and say so** — an unclassified path is an unknown blast radius, so it escalates rather than falling to L1. Add the row it should have matched in the same PR. |

**The level is a floor, not a ceiling.**

- **Escalate freely, never silently downgrade.** Two rows applying means the higher
  wins — a PR that is "mostly docs" but edits one line of `render/` is L3. In
  doubt, go up one: an unnecessary golden run costs minutes, a missed one costs a
  pixel regression that lands. **A failure that surprises you is an escalation
  signal**, not just a gate to fix.
- **Rebasing onto a new base re-runs the level**, because the union of two
  independently-green changes is not itself proven green (#311).
- **A level you cannot run is handed off, not dropped.** The headless Linux box
  marks L3's window/browser steps `n/a`; if *your* platform cannot run part of
  your declared level it stays 🤝 with the exact commands, and the PR still says L3.
- **§4.7 needs a large MP4** when the media layer changed: **> 4 GiB** exercises
  the offset-truncation trap, a **multi-hundred-GiB** file additionally proves the
  ranged-read economics. Name the file and size in the PR. **With no file over
  4 GiB that row is 🤝 — never ✅ and never a quiet `n/a`.**

**Any change that reaches pixels must land the golden suite green on a real GPU**
(`crates/trd-core/tests/golden_render.rs`, `#[ignore]`), on every platform that
has one — Windows included; don't defer it to Linux. Regenerate goldens **only**
for an *intended* visual change:

```sh
python3 scripts/golden_fixtures.py    # rebuild the .arrow fixtures (needs uv + ffmpeg)
TRD_UPDATE_GOLDENS=1 cargo test -p trd-core --test golden_render -- --ignored
```

**Where a test lives — by kind, not by size (#305):** a **unit test** goes inline
in the module it pins (`#[cfg(test)] mod tests`, **however long**); an
**integration test** gets its own file under `crates/<crate>/tests/`. There is no
`src/**/tests.rs` middle form — [why](docs/testing.md#where-a-test-lives--by-kind-not-by-size-305).

## PR workflow

- **pr_first:** push to a feature branch and open a **draft PR** early; use the PR
  as the working surface. **branch naming:** `feat/`, `fix/`, `docs/` + `<topic>`.
- **auto_merge: small** — small, low-risk PRs may be squash-merged once the gates
  are green. Risky PRs (public API, schemas, migrations, auth, infra) need human
  review. **merge strategy:** squash; a PR resolving an issue carries `Closes #nn`.
- **Handoff:** for whichever platform you cannot run yourself, leave the exact
  commands + expected result in **both** the issue and the PR.

### Issue titles

Every issue title **starts with a bracketed category tag**: `[Tag] <concise summary>`.
Pick the single tag that best fits its primary intent.

| Tag | Meaning |
|---|---|
| `[Epic]` | umbrella / tracking issue spanning multiple slices |
| `[Feature]` | a shippable capability grouping several slices (narrower than `[Epic]`, broader than one `[Slice]`) |
| `[Slice]` | one vertical slice increment (independently end-to-end verifiable) |
| `[Design]` · `[Plan]` | a spec settled *before* implementation · a roadmap across issues |
| `[Refactoring]` | a behaviour-preserving restructure (regression net must stay green) |
| `[Investigation]` · `[Eval]` | a research spike · an evaluation / benchmark |
| `[Risk]` · `[Test]` | a hardening task · a test-only slice (fixtures, goldens) |

Others in use as needed: `[Ops]`, `[Demo]`, `[Prep]`, `[Integration]`, `[Docs]`.

### Verification matrix

Report dual-platform results as an icon-led matrix plus a handoff checklist —
**on every PR, mirrored in the issue. Never report gates as bare prose.** Keep to
this glyph set so the format stays greppable; the gate glyphs are listed in the
order the rows go in, L1 first:

| Kind | Glyphs |
|---|---|
| **status** | ✅ passed · ❌ failed · ⏳ not yet run · 🤝 handed off · n/a not applicable |
| **platform** | 🪟 Windows · 🐧 Linux/Nix |
| **gate** | 🎨 fmt · 📎 clippy · 🕸️ clippy-wasm · 🧪 tests · 🔀 decoder-parity · 📚 rustdoc · 🌐 tsc/biome · 🖼️ golden-render · 🎮 gpu-tests · 🖥️ window e2e (§4.2/4.3) · 🎬 video-editor e2e (§4.5/4.6) · 📼 large-file seek (§4.7) |

**Every row is always present**, in that order. A gate the level excludes reads
`n/a (L1)` — naming the level that excluded it — so a skipped gate is always a
decision, never an omission: dropping a row is how an unresolved rustdoc link
reached `main` (#336). The copy-paste template is in
[`docs/testing.md`](docs/testing.md#the-matrix-template).

**`n/a` means the *level* excludes the gate — never that the other platform ran
it.** Every gate inside your declared level runs on **both** platforms, or it is
🤝 with the exact commands. An argument that a gate *cannot* be affected — an
unchanged input, a nix cache hit, a byte-identical derivation — is reasoning, not
a run: put it in the PR prose, never in the cell. Cross-platform faults are
precisely the ones such arguments survive, because what differs is the toolchain,
the path separator or the line ending, not the source.

**Re-post the completed matrix after a handoff** as a new comment on the PR (and
on the issue), with that platform's column flipped from 🤝 to ✅ and the handoff
items ticked. The completed matrix must be *visible*, not merely described.

### Worktrees

**Keep the git root checkout on `main` at all times** and **update local `main`
before creating a worktree**, so the branch starts from an up-to-date base:

```sh
git switch main && git pull
git worktree add .worktree/<topic> -b feat/<topic>
```

**Never check out a feature branch in the root itself.** Remove the worktree once
the PR merges (`git worktree remove .worktree/<topic>`). There is only **one**
tracked `AGENTS.md` (repo root); a worktree's copy is that file on its branch,
not a second one to reconcile.

## Documentation

**`README.md` is a lean entry point; the detail lives in `docs/`.** Whenever a
change updates one, update the affected page(s) in the **same** PR — and
vice-versa. Don't let them drift.

**The list of pages and what each covers lives in
[`README.md`](README.md#documentation), not here** — a second copy is how this
file's own gate list rotted (#336). Add new pages there. The two an agent needs
most often: [`docs/testing.md`](docs/testing.md) (how to run every gate) and
[`docs/architecture.md`](docs/architecture.md) (what they protect).
